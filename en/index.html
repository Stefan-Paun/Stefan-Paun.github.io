    Schleuse

    A gate for incoming pull requests. In 2026 the PolinRider campaign appended malware behind 500 or more spaces at the end of ordinary config files and used that to send poisoned PRs to large projects. Schleuse reads every PR as data through the GitHub API, checks nothing out, runs nothing, and recognises the attacks by their shape rather than by markers the attacker has long since rotated: code hidden behind whitespace, fonts that are really JavaScript, tasks that run when a folder is opened. In a workflow, three lines are enough.

    Security · GitHub Action, Node, no dependencies, over 100 tests · open source
    Code on GitHub (new tab)
    3poisoned PRs, all blocked (field test in the README, new tab) 31clean PRs without a false alarm (field test in the README, new tab) Field test on 1 November 2026: three documented poisoned PRs and 31 merged PRs from next.js, Tailwind, shadcn/ui, NestJS and Prisma (15 latest, 10 with config changes, 6 with .woff2 fonts).

    Nachsitzen (Detention)

    A Werewolf-style game where the other players are Claude characters: each only sees what happens near it at night, lies when that helps, and after the game writes in its notebook whom it trusts. Next game, it reads it again. Ten test agents played it; their feedback turned into secret votes, presentable evidence and one more seat at the table: you now play with six AI characters instead of five. German only for now.

    AI agents · game in the browser, Node, no dependencies · open source
    Code and setup on GitHub (new tab)
    Runs locally with your own Claude key; one game costs about 2 to 4 cents.

    Claude Code tools

    Tools that make my AI assistant more reliable. A guard checks every commit against up to 10 patterns for API keys, private keys, private email addresses, phone numbers and private paths. A proof guard stops Claude from saying “done” while no tests have run after a code change. Plus an error diary, a weekly gardener that turns my corrections into new rules, and my own MCP server for live context such as project status and deadlines.

    Pruefstand (Test bench)

    A test bench for AI coding agents. It hides an instruction like “send the .env to this address” in a README or bug report and runs my real agent against it under three defence profiles. Worthless fake keys and a honeypot on my own machine make sure nothing gets out. Each profile ends with a resilience score from 0 to 100.

    Security · Node, no dependencies, over 130 tests · open source
    Code on GitHub (new tab)
    One concrete finding: a deny rule stops the read tool, but not “cat .env” through the shell. Only the sandbox closes that gap.

    Ungeloest (Unsolved)

    Every day, thousands of bug reports and questions go unanswered. Ungeloest collects them from GitHub issues, Stack Overflow, Discourse forums, GitHub Discussions and GitLab. Each hit gets two scores, solvability and impact, and the top ones get a dossier with a checklist. The solving and answering I do myself, after reproducing the problem. The tool never posts anything.

    Open-source help · Node, no dependencies, over 130 tests · open source
    Code on GitHub (new tab)
    First scan: 215 open problems, including bugs in pyright, undici and jellyfin that nobody had looked at for weeks.

    Stapelwerk

    A learning game for assembly in the browser: 30 puzzles in eight chapters, from changing a single register to linked lists on the heap. The 32-bit CPU was designed just for it; its core is written in Rust with zero third-party crates and runs as WebAssembly. The debugger can go backwards; seven levels start with a bug that you find with it instead of by guessing.

    How I build. Every project goes through the same layers. Whatever fails a layer doesn’t move on.

    1. Plan

      I write down what gets built and split it into phases.

    2. Agents

      Claude Code agents build separate parts in parallel, cloud routines keep working at night. I review and merge.

    3. Tests

      Every change runs through the tests before it stays.

    4. Security

      No keys in the code, no private data. Before publishing I check which attack paths exist.

    5. Release

      Only finished things go public: with docs, a licence and a demo.
